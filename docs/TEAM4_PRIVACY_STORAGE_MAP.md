# Team 4 — Privacy Storage Map

This map is evidence for Team 4's Safety/Privacy boundary. It records current repository behavior; it is not a retention-policy invention.

`No app-level TTL found` means the inspected schema/path does not currently define a time-based deletion rule. That is not a promise of indefinite retention and not a newly approved policy.

## Key privacy invariants traced from code/tests

1. **Live Conversation text is RAM-first.** `ConversationServer` explicitly says raw live-message content is never persisted by that module and defines bounded message/replay lifetimes.
2. **Local retention is participant-controlled IndexedDB.** Keep retains; Summary removes transcript and stores only the chosen summary; Fade removes transcript and summary; delete-one/delete-all remove kept local Conversation records and associated local messages/voice notes.
3. **Encrypted backup is local encryption.** PBKDF2-SHA256 + AES-GCM is used before an exported backup envelope is produced; the passphrase is input to derivation and is not written into the envelope.
4. **Google sync is encrypted before provider upload.** Only allowlisted record categories are accepted; token/authorization-like keys are forbidden; server-side sync state caches metadata rather than plaintext records.
5. **Safety evidence is intentionally separate from ordinary retention.** A Report may durably preserve the authoritative current targeted snapshot or bounded participant context even if later Unsend removes participant-visible content. Safety records are excluded from optional continuity sync.
6. **Diagnostics are content-blind.** The Phoenix Channel crash translator retains failure class and source location while dropping topic, socket assigns, last inbound payload and product state.
7. **No universal erasure claim.** Local deletion, Unsend, Report evidence, server Memory, durable safety records and optional Google sync each have distinct authorities and must not be described as one global deletion operation.
